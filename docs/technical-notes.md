# 기술 기록

## 음악을 이미지로 표현하기

`Creating_data_set_from_midifiles.ipynb`는 MIDI note-on/note-off를 음높이·시작 시각·길이로 읽고, `ticks × 4 / ticks_per_beat`로 시간을 16분음표 단위로 변환합니다. 4/4의 8마디를 128개 시간 칸 × 128개 음높이의 이진 배열에 표시합니다.

MIDI 0–35, 60–71, 112–127 행을 삭제하면 **36–59와 72–111의 64개 음높이**가 남습니다. 이어 시간축을 앞·뒤 64칸으로 나눠 **4마디 이미지 두 개**를 만듭니다. 단일 트랙에서 멜로디와 화성을 음역으로 구분하므로, 벨로시티나 악기 음색은 이미지의 학습 대상이 아닙니다. 학습 직전에 `(x - 0.5) / 0.5`로 [-1, 1] 범위에 맞춥니다. 검사용 노트북은 행 삭제가 주석 처리되어 128×128 전체를 보여 줍니다.

## 64×64 모델

근거: `Music_gen/music_gen_sil_geon_64.ipynb`, `배포ver1.2.ipynb`.

| 항목 | 구현 |
| --- | --- |
| 환경 | Python, Google Colab, TensorFlow/Keras |
| 입력 잡음 | 표준정규분포, 100차원 |
| 생성자 시작 | Dense → 8×8×256, BatchNorm, LeakyReLU |
| 생성자 합성곱 | Conv2DTranspose 128→64→32→1, 5×5 커널 |
| 공간 크기 | 8×8 → 8×8 → 16×16 → 32×32 → 64×64 |
| 출력 | 64×64×1, tanh |
| 판별자 | Conv2D 64→128, 5×5 커널, stride 2, LeakyReLU, Dropout 0.3, Flatten, Dense 1 |
| 손실 | BinaryCrossentropy(from_logits=True) |
| 최적화 | 각각 Adam, 학습률 0.0001 |
| 배치 | 256 |
| 코드의 학습 설정 | EPOCHS=20000 |
| 원본 저장 주기 | 10000 epoch 이후 50 epoch마다 |

학습 단계마다 가짜 이미지 256개를 생성합니다. 실제 데이터의 마지막 배치가 작아도 잡음 수를 바꾸지 않는 원본 동작을 유지했습니다. 학습과 배포의 모델 구조는 동일합니다.

TensorFlow 튜토리얼의 DCGAN 패턴을 음악 이미지에 맞게 확장했습니다. 기여의 핵심은 음악 데이터 규격화, MIDI↔이미지 처리, 음악 해상도에 맞춘 모델 적용과 실제 제작 연결입니다. DCGAN 자체를 새로 고안했다는 의미는 아닙니다.

## MIDI 복원과 배포

배포 v1.2는 생성 결과를 `(x + 1) / 2`로 복원한 뒤 `np.around`로 이진화합니다. 제거한 음역을 0으로 삽입해 128행으로 되돌리고, 각 음높이에서 연속된 활성 칸을 하나의 음으로 묶습니다. 한 칸은 0.25 beat이며 MIDIUtil로 velocity 80의 MIDI를 저장합니다. 기본 출력 템포는 100 BPM으로 조절 가능하고, 학습 자료 제작 템포 120 BPM과는 별개입니다.

배포 v1.1부터 FluidSynth 오디오 미리듣기가 있으며, v1.2에는 출력 BPM과 시간 기반 파일명이 있습니다. 공개본에서는 오디오 과정을 선택 셀로 분리했습니다.

## 로컬 보관 자료

| 원본 배열 | 실제 크기 | 자료형 |
| --- | --- | --- |
| Data/data_set.npy | 3×128×128 | float64 |
| Data/data_set/data_set.npy | 224×64×64 | float64 |
| Data/data_set/data_set_64.npy | 224×64×64 | float64 |
| Data/data_set/data_set_64_check.npy | 552×64×64 | float64 |
| Data/data_set/data_set_64_sil_jeon.npy | 552×64×64 | float64 |

학습 원본은 `data_set_64_sil_jeon.npy`를 로드합니다. 552는 이미지 수이며 곡 수가 아닙니다. 한 MIDI에서 두 이미지를 만드는 코드와 일치하는 형태이지만, 현재 전체 MIDI가 최종 배열과 일대일로 대응한다고 단정하지 않았습니다.

배포본은 `ckpt-80`을 지정하며 해당 파일도 보관되어 있습니다. 번호는 저장 횟수이지 epoch 번호가 아닙니다. 기획 문서에는 14,000번째 학습 결과를 사용한 기록이 있으나, 원본 이미지 저장 코드에 `epoch+10000` 오프셋이 있어 파일명의 숫자를 실제 학습 횟수로 단정할 수 없습니다. README 예시는 `epoch_images_sil_jeon/image_at_epoch_24000.png`를 그대로 복사했습니다.

## 차트 선별

CSV 날짜에서 `199`가 들어가는 행을 선별하고 `weeks_on_chart` 내림차순 정렬 후 `song`만으로 중복을 제거합니다. 동명의 다른 곡이 합쳐질 수 있는 당시 로직을 유지했습니다. 남아 있는 배분 단계는 0 기준 120–239번을 해완·보람·동진에게 40개씩, 240–299번을 재명에게 60개 배정합니다. 전체 프로젝트의 모든 배분 단계를 담은 코드는 아닙니다.

## 알려진 제약

- MIDI 읽기는 단일 트랙 규칙을 전제로 합니다. 빈 파일, 여러 트랙의 독립적인 시간, 채널별 중첩 음을 일반적으로 처리하지 않습니다.
- 마지막 음의 시작이 128칸 이상이면 첫 16칸을 제외하는 원본 처리는 범용 못갖춘마디 분석이 아닙니다.
- 연속된 같은 음은 이미지에서 이어질 수 있어 재타격 정보가 소실됩니다.
- 현재 TensorFlow/Keras와 2022년 체크포인트의 복원 호환성은 별도 확인이 필요합니다.
- 정량 생성 품질이나 히트 가능성 예측 성능을 검증한 기록은 없습니다.
